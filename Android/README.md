# 天书奇谈 Android 无头客户端

这个目录是一个原生 Android 工程。它不复刻 Flash 画面，而是把现有 Windows 客户端里已经整理出来的登录、心跳、地图传送、跑环、独立自动战斗、除暴、登山爬塔和帮派捐献协议迁移到 Kotlin 协议库，再由 Android 前台服务长期保持 TCP 会话。

## 模块

- `:core`：纯 Kotlin/JVM 协议库和无头自动化状态机，可在没有 Android SDK 的机器上运行单元测试。
- `:app`：Android APK、设置页、前台服务、常驻通知、密码加密保存、开机恢复和本地服务状态。

`settings.gradle.kts` 会在检测到 `local.properties` 的 `sdk.dir`、`ANDROID_HOME` 或 `ANDROID_SDK_ROOT` 时包含 `:app`。没有 Android SDK 时只包含 `:core`，方便先跑协议测试。

## 已实现入口

- 设置页保存入口服地址、候选端口、账号、线路、角色槽、`operationCom`、强制登录和自动登录开关。
- 密码通过 Android Keystore 的 AES/GCM 保存，账号和普通配置通过 DataStore Preferences 保存。
- 功能按钮包括“只登录并常驻”“日常全套”“自动跑环”“独立自动战斗”“自动除暴”“登山爬塔”“自动捐献”。
- “日常全套”当前只按队列执行“自动除暴 → 自动跑环”；自动捐献和登山爬塔仍保留为单独按钮。
- 前台服务使用常驻通知显示当前状态、自动化和最近心跳，并提供停止和重连动作。
- 页面顶部显示版本、运行状态、当前地图、当前随机跑环任务与进度；“停止当前任务（保持在线）”会清空待启动任务，保留游戏连接。
- App 在私有目录滚动保存最近的运行事件（单文件上限 1 MiB），只记录协议号、长度和状态，不保存密码或完整协议载荷。
- 24 小时模式会请求通知权限、引导加入电池优化白名单，并在服务活动期间持有轻量 `PARTIAL_WAKE_LOCK`。
- 开机自启由 `BootReceiver` 恢复，前提是设置中同时开启“开机自启”和“自动登录”。

## 协议与自动化原则

- `GameSession` 负责入口服登录、线路选择、游戏服票据登录、角色选择、进图、心跳响应、共享序号和帧分发。
- 每次登录或传送收到地图起点 `0x0016` 后，会按 Flash 实际顺序发送 `0x002E/action 0xCE`，等待约 60ms 再发送 `0x002E/action 0x47`；跑环走步会在这两条地图就绪动作之后开始。
- 只响应服务端 `0x0053` 心跳，不主动定时发送心跳。
- 65 秒未收到服务器心跳会判定会话失活，服务按设置断线重连并重新登录。
- Wi-Fi/移动网络切换会立即淘汰旧连接及其回调，等待新默认网络通过联网验证后，用该网络重新建立入口服和游戏服会话；无需等满 65 秒。
- 重新登录必须收到本次连接的地图信息、匹配的可走格、合法任务列表，并完成起点进图确认后才显示“在线”和恢复任务。任务列表未到齐时显示同步中，30 秒超时则按设置重试，不用空缓存启动跑环或除暴。
- 除暴重新登录后也会解析当前任务列表中的 `1984` 任务，继续当前目标；跑环继续从当前随机任务恢复，不复用旧连接的坐标、任务或确认 token。
- 所有发包自动化通过 `AutomationManager` 的 owner 锁互斥，同一时间只允许一个功能发送协议包。
- 跑环启动时会接管独立自动战斗，避免重复走步、恢复或战斗推进包。
- 战斗开始后暂停走步，按真实 `0x002C` 行动提示等待 650ms 发送 `0x001F`，支持同轮人/宠物切换；`0x002B` 解析为倒计时和显示回合，`0x002D` 不视为客户端请求确认。收到 `0x002F` 后才恢复走步或交环。
- Android 跑环以 Windows `src/Protocol/RunLoopAutomation.cs` 为行为基准：柳先元使用 `93290 / 地图 72 / (23,132)`，传送确认等待 160ms、到图后等待 450ms 打开 NPC、功能确认后等待 180ms 选择功能。
- 登录时会解析 `0x003D` 当前任务列表；若柳先元提示“还有未完成的任务”，服务会自动重新登录一次同步任务后续跑，避免停在 NPC 处。
- 已存在的跑环会从任务名、描述和进度恢复当前环。例如第 2 环“怒焰祭坛 / 火石 0/5 / 钱不与”会直接前往怒焰祭坛继续，不会再次向柳先元领取第 1 环。
- 环号只用于校验任务先后关系；每一环的战斗地图、目标、完成进度以及交付 NPC、地图和坐标都从本次实时 `0x003D/0x003E` 任务快照重新解析，不按第 K 环绑定固定 NPC。
- 同时接收 `0x0027` 任务状态增量：核对任务 ID、当前目标和所需数量后更新进度，不要求服务端重发完整任务；待交付或任务删除后忽略旧状态。
- 随 APK 打包 Windows 已采集 NPC 目录的 655 条有效记录；当前会话仍会从 `0x001C/0x006A` 更新 NPC 信息。
- 普通环必须收到任务 `140000000` 的 `0x003F` 删除确认才计数；第 20 环确认后等待 250ms 返回柳先元，最多执行 6 轮/120 环。
- 延迟发包或服务器报文处理异常会让当前自动化进入 Failed 并释放 owner，之后可再次启动，不会留下“仍在运行”的假状态。
- 已确认战斗期间不发走步；非战斗期间若服务端回复“当前状态不能走动”，立即停止当前跑环，避免持续发送无效走步。
- 入口认证及游戏进图有 30 秒无响应保护；在线后地图初始化超时也会断开，服务按重连设置恢复当前任务。日常队列已进入跑环时恢复跑环阶段。
- 当缺少确认 token、地图数据、NPC 函数或任务字段时，状态机会停止或等待，不发送猜测封包。

## 构建

有 Android SDK 时：

```powershell
cd Android
.\gradlew.bat test
.\gradlew.bat :app:assembleDebug
```

当前本机已经在 `Android/.android-sdk` 配置了 Android SDK Platform 37.0、Sources 37.0、Build-Tools 37.0.0 和 Platform-Tools，并通过 `Android/local.properties` 指向该 SDK。`compileSdk/targetSdk 37` 会由 AGP 9 匹配到 `platforms/android-37.0`。

如果换到只有 Android SDK 36 的机器临时验证，可以用覆盖参数：

```powershell
cd Android
.\gradlew.bat "-Ptianshu.compileSdk=36" "-Ptianshu.targetSdk=36" :app:assembleDebug
```

没有 Android SDK 时：

```powershell
cd Android
.\gradlew.bat :core:test
```

如果需要固定本地 SDK 路径，新建 `Android/local.properties`：

```properties
sdk.dir=C\:\\Android\\Sdk
```

Debug APK 产物路径为 `Android/app/build/outputs/apk/debug/app-debug.apk`。

跑环实现、回放证据与实机验证边界见 [跑环对齐记录](docs/runloop-parity.md)。

Wi-Fi/移动网络切换的故障原因、恢复流程与验证记录见 [切网恢复修复](docs/network-recovery.md)。

## 当前限制

这个版本按本地自用、侧载 APK 设计。24 小时不间断是“用户授权后尽量持续运行并自动恢复”的工程目标，实际稳定性还会受 Android 版本、厂商省电策略、网络质量和白名单状态影响。`specialUse` 前台服务如果要上架 Google Play，需要单独准备政策说明。

移植范围保留在无头协议功能内；Windows 专属的 EasyHook、WinForms 抓包界面、原子录制、Lua 场景仍留在 Windows 客户端。
