# Android 跑环对齐记录

## 行为来源

任务协调以 `src/Protocol/RunLoopAutomation.cs` 为准。Windows 协调器运行在 Flash 客户端旁边；Android 无头版还必须承担 Flash 的进图、战斗响应和任务状态更新职责。仅复制协调器的走步定时器无法完成这个链路。

| 环节 | 实现与核对依据 |
| --- | --- |
| 从当前环继续 | 解析登录任务列表 `003D` 和任务更新 `003E`，逐条隔离记录；地图、NPC、坐标、目标均来自本次随机任务 |
| 领取与交付 | 柳先元 `93290 / 72 / (23,132)`；确认传送 160ms、开 NPC 450ms、选功能 180ms，使用实时 token 和共享序号 |
| 进图 | `0055` 地图、`003C` 格点、`0016` 起点；`002E/action CE` 后约 60ms 发 `002E/action 47`，此后才允许自动化动作 |
| 巡逻 | 当前 C# 默认 200ms、最多四个相邻可走点、恢复间隔 4 秒；缺少可走格不猜坐标 |
| 战斗 | `002A` 暂停巡逻；`002C` 人/宠物行动提示后 650ms 发 `001F`；`002B` 为倒计时和显示回合，`002D` 为指定角色停表；`002E` 回合结果及 `002F` 战斗结束驱动后续操作 |
| 进度 | 支持 `0027` 的 taskId、条目数、状态文字、完成标志；匹配当前目标和总数，拒绝倒退、错误任务和截断数据 |
| 环间推进 | 收到 `140000000` 的 `003F` 删除确认才计数；第 20 环删除后 250ms 重新领取，最多六轮；旧任务回发和重复删除不重复计数 |
| 接管与停止 | 独立自动战斗和跑环共享战斗状态、恢复时钟、请求序号；用户停止会取消已排队启动和延迟动作 |
| 断线恢复 | 网络切换淘汰旧会话，重新同步地图、可走格、任务列表及起点确认后恢复；进入跑环后的日常队列恢复跑环阶段，不重新执行除暴 |

战斗字段还核对了本机 Flash 反编译文件 `net/handler/_2d839e4711c942ea7dc158c008a42e27.as` 与 `net/_89cbca94e7e1aa18b5e3b86e35a0f9ba.as`；任务状态核对 `net/handler/_92a8ad485c6fa3dece28c6f4157ebe59.as`。650ms 延时来自 `BountyAutomation.HandleBattlePrompt`，不是把倒计时秒数误当成回合键。

## 可重复验证

```powershell
cd Android
.\gradlew.bat :core:test :app:assembleDebug :app:lintDebug
```

- `RunLoopParityTest`：领取、动态第 1–20 环、不同 NPC/地图、路由、格点、超时、六轮 120 环。
- `RunLoopBattleIntegrationTest`：战斗中不走步，`003E` 或仅 `0027` 更新完成后等待 `002F` 再交环，接管不重复回合/恢复，120 环混合击杀与对话。
- `RunLoopTaskRecordTest` / `RunLoopTaskStatusTest`：Windows 真实任务记录、相邻任务隔离、用户第 2 环火石任务、任务状态增量与异常输入。
- `HeadlessBattleControllerTest`：录制战斗帧、非 25 秒倒计时、人宠切换、重复提示、回合结果与结束取消。
- `GameSessionIntegrationTest`：本地入口服/游戏服 TCP 链路、进图动作顺序、登录与地图初始化超时、停止取消旧启动；真实录制的第 2 环冯奇菜单交付后进入第 3 环舞修罗。
- `MapReadinessTest`：地图就绪门控和旧连接缓冲清理；`ProtocolTest` 验证走步、进图和心跳字节向量。

测试使用本地模拟服务器以及录制报文，不向官方服务器发送测试包。`core/src/test/resources/runloop-recorded/` 仅保存任务、地图和 NPC 帧，不含账号、密码、票据。


构建、静态检查、录制与模拟回放通过，不等于实机已跑满六轮。最终还需要在手机上确认当前环进度持续增长、战后交环、第 20 环重新领取，以及实际网络下的断线恢复。当前工作环境没有已连接的 ADB 设备；本轮仅生成 APK，没有安装或执行官方服务器账号测试。未知任务格式、未记录入口和缺失确认数据仍会安全停止并显示原因。
