# Android 切网恢复修复（0.1.2）

## 故障与原因

用户反馈：Wi-Fi 突然断开并切换到移动网络，重新上线后界面显示“已在线”，但地图和跑环任务为空，除暴与跑环均无法启动。

代码核对发现旧实现没有监听默认网络变化，只依靠读错误或 65 秒心跳失活处理旧连接；进图起点后的两条确认发完即发布在线事件，服务再固定等 750ms 启动自动化，没有确认地图和任务是否收到。切网后延迟到达的数据、旧连接回调与新登录流程可能交错。旧连接阻塞发包时，状态读取与断开流程还可能等待自动化锁，挡住本应先关闭的 socket。

这些问题已在代码中修复。本次没有连接手机，不能据此认定用户手机上的所有网络条件均已通过验收。

## 修复后的流程

1. 监听默认网络的 available/capabilities/lost 事件，忽略已淘汰网络迟到的回调。默认网络变化或失去联网能力时，立即关闭旧连接；新网络具有 INTERNET 与 VALIDATED 能力后，按设置发起重连。
2. 每次登录创建新的 `GameSession`，入口服与游戏服 socket 均由这一代默认网络的 `SocketFactory` 创建。旧会话事件携带创建时的登录代号，不能覆盖新会话状态；旧的任务启动、任务刷新和重连回调全部取消。
3. 关闭 socket 在自动化锁与 writer 锁之前进行；UI/网络监听读取不可变状态快照，不等待正在发包的自动化锁。断开原子地清除在线状态，迟到的进图/自动化回调不能把它写回在线。
4. 每次新登录清空地图、格点、任务、战斗状态、序号、心跳和延迟缓冲。当前连接必须收到 `0055` 地图、匹配地图 ID 的 `003C` 可走格、合法 `003D` 任务列表，以及 `0016` 起点对应的 `002E/CE → 60ms → 002E/47` 确认，才发布在线与恢复自动化。
5. 同步过程中继续响应服务器心跳。缺少数据时显示具体等待项；30 秒初始化超时会结束该连接，并按失败重登设置重试。空任务列表合法，未收到或解压失败的任务列表不能当成空列表。在线断线采用“网络断线自动重连”设置，登录阶段失败采用“失败后重新登录”设置。
6. 跑环从新列表中恢复当前随机环的目标、进度和交付 NPC。除暴恢复列表中的 `1984` 任务；已在战斗中时继续响应战斗提示，等待战斗结束再传送。日常队列仍为除暴 → 跑环，已经进入跑环的队列重连后继续跑环阶段。

地图切换仍沿用 Windows/Flash 的进图协议顺序；任务列表是每次连接的同步条件，不要求每次普通传送都重发列表。已有同一连接的任务状态可以继续使用，跨连接不可复用。

实现依据：[Android 默认网络及回调](https://developer.android.com/develop/connectivity/network-ops/reading-network-state)、[Network.getSocketFactory](https://developer.android.com/reference/android/net/Network#getSocketFactory())。网络切换不会把已有 TCP 会话迁移到新网络，恢复需要新的连接和游戏登录初始化。

## 验证

```powershell
cd Android
.\gradlew.bat :core:test :app:assembleDebug :app:lintDebug
```

- 本地入口服/游戏服 TCP 测试：突然断流、再次登录、起点先到而地图/任务延迟超过 750ms；未收齐时不在线、不启动自动化，收齐后分别恢复当前跑环与除暴。
- 缺失任务列表：不能上线，报告缺少任务列表并断开；一次故障只发布一次断开事件。
- 阻塞写测试：发包一直等待时状态查询仍立即返回，断开会关闭 socket 并解除阻塞，断开后不会恢复成在线。
- 默认网络测试：Wi-Fi → 移动网络、旧 Wi-Fi 延迟丢失通知、重复回调、网络失去验证、快速多次切换。
- 协议测试：合法空任务列表、录制中省略校验尾部的压缩列表、截断数据；除暴战斗内恢复后只响应一次行动提示，目标删除后等战斗结束再返回 NPC。
