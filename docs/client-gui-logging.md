# GUI 统一运行日志

## 目的与界面位置

本地客户端的自动登录、自动除暴、自动捐献、自动跑环、登山爬塔、地图传送、BGM 和多开管理共用一套结构化运行日志。日志固定在右侧工作台底部，切换功能页不会丢失；工具栏的“日志”按钮可以折叠或恢复日志区，分隔条可以调整高度。

日志表格按“时间、级别、模块、状态、消息”显示，并支持模块、级别和关键词筛选、自动滚动、多选复制及手动清空。错误和警告行使用不同底色，便于长流程中快速定位异常。

## 三类日志的边界

| 类型 | 保存位置 | 用途 | 清理方式 |
| --- | --- | --- | --- |
| 统一运行日志 | 当前客户端进程内存，最多 10,000 条 | 查看登录、自动化、BGM、多开等用户可理解的运行过程 | 底部日志区“清空日志”；不会影响其他数据 |
| 审计日志 | “审计日志”页，并由工作台事件写入当前会话 SQLite | 协议引擎、Lua、原子操作、规则和会话事件审计 | 不随统一运行日志清空；按会话数据库生命周期管理 |
| 启动器诊断日志 | 当前实例目录下的 `logs/launcher.log` 等文件 | 启动、Hook、代理及异常堆栈等底层诊断 | 由使用者按文件管理；GUI 不会删除 |

统一运行日志只保存在内存中，不会再生成一份重复的磁盘日志。达到 10,000 条后会自动淘汰最旧记录；表格使用虚拟行和定时批量刷新，避免每条状态都扩张文本控件并触发重绘。

## 代码接入

日志核心位于 `src/ClientLogging.cs`，不依赖 WinForms：

```csharp
public sealed class ExampleFeature
{
    private readonly IClientLogSink log;

    public ExampleFeature(IClientLogSink log)
    {
        this.log = log ?? NullClientLogSink.Instance;
    }

    public void Start()
    {
        log.Publish("示例功能", ClientLogLevel.Info, "Starting", "功能开始执行。");
    }
}
```

已有自动化协调器仍以 `StatusChanged` 作为唯一状态来源，`ProtocolWorkbenchControl` 将这些事件桥接到 `ClientLogHub`。新功能如果已经提供状态事件，可以沿用同样的桥接方式；没有状态事件时可直接依赖 `IClientLogSink`。保留接受空日志实现的构造重载，可避免功能在无 GUI 或测试环境中被迫依赖 WinForms。

## 安全约束

- 不得把密码、DPAPI 解密结果、登录票据、会话密钥或完整数据包原文传给 `Publish`。
- 登录日志只能记录阶段和失败原因，不回显密码输入框内容。
- 需要查看原始或有效数据包时使用“数据包”页及 SQLite，而不是统一运行日志。
- 协议中的实时 token、序号等仅在确有调试需要且不属于登录凭据时记录摘要；不要把认证材料写入消息。

## 维护约定

- 模块名使用稳定的中文功能名，例如“自动除暴”“地图传送”，避免把动态地图名或账号名用作模块名。
- 状态字段使用协调器枚举名称；失败使用 `Error`，主动停止使用 `Warning`，其他正常阶段使用 `Info`。
- “清空显示缓存”管理数据包、协议帧和状态图缓存；“清空日志”只管理统一运行日志，两者互不影响。
