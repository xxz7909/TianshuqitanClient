# 帮派捐献协议与自动化状态机

本页结论来自 `session-20260901-110112-998-捐献上古神器碎片.sqlite` 和 `session-20260901-114436-598-点了确定的捐献.sqlite` 的完整会话回放。实现不重放录制时的背包格、功能 ID 或请求序号。

## 已确认对象

-zx2990698929帮会捐献官 NPC：`93631`（`0x00016DBF`）。
-qaz14747NPC 功能名称：`帮派捐献`。录制中的功能 ID 是 `9991523`，但客户端每次从 `SC_NPC_DIALOG` 按功能名称重新解析，不能硬编码。
- 当前自动捐献物品：`上古神器碎片(一等)`，模板 ID `115000140`。
- 源背包 ID：`1`；捐献临时容器 ID：`0x0099`。

## 动态背包查询

登录时已有的背包物品不会逐件发送 `SC_ITEM_UPDATE`。服务端先发送 `SC_INVENTORY_SNAPSHOT_ZLIB (0x00B2)`：偏移 4 是 zlib 数据长度，偏移 6 开始是 RFC 1950 zlib 流。解压后每条物品记录仍以 `bag_id / slot / stack_count / unknown / name_length / name` 开头。程序在初始快照中按精确道具名称建立索引；本次实测会话中自动解析到背包 `1`、格 `13`、数量 `730`。

后续物品变化使用 `SC_ITEM_UPDATE (0x0024)`：

`SC_ITEM_UPDATE (0x0024)` 的首部布局：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| 4 | u16 BE | 背包 ID |
| 6 | u16 BE | 背包格 |
| 8 | u16 BE | 堆叠数量 |

程序检查包内的 UTF-8 道具名称和 ASCII 模板 ID，自动维护 `背包格 -> 数量` 索引。录制中同一道具先后位于 `0x007E` 和 `0x0012`，证明格子不能固定。`SC_ITEM_REMOVE (0x0025)` 用偏移 4 的背包 ID 和偏移 6 的背包格删除索引；道具换格或一格耗尽后会自动选择当前仍存在的目标堆叠，用户无需输入位置。

## 发包流程

1. `CS_NPC_OPEN (0x0016)`：NPC ID + 当前请求序号。
2. 从 `SC_NPC_DIALOG (0x001D)` 中按精确标签 `帮派捐献` 读取当前功能 ID。
3. `CS_NPC_FUNCTION (0x0017)`：NPC ID + 动态功能 ID + 当前请求序号。
4. 等待 `SC_DONATION_PANEL_STATE (0x03C6)` 的状态值 `3`；状态 `2` 表示放弃/不可捐献，立即停发。
5. 每次发送一个 18 字节 `CS_ITEM_TRANSFER (0x001D)`：

```text
u16 frame_length = 18
u16 opcode       = 0x001D
u16 amount       = 1
u16 source_slot  = 动态背包格
u16 target       = 0x0099
u32 reserved     = 0
u32 sequence     = 当前请求序号
```

录制样例（仅用于验证布局）：

```text
00 12 00 1D 00 01 00 12 00 99 00 00 00 00 00 00 01 12
```

6. 不能把上一步当成捐献完成。等待服务端以 `SC_ITEM_UPDATE (0x0024)` 返回 `bag_id=0x0099 / slot=0` 且其中物品名称或模板 ID 匹配，确认碎片已经进入临时捐献栏。
7. 发送 24 字节 `CS_UI_ACTION (0x002E)`，其中 `action_id=0x03B9`，等价于点击面板上的“捐献”按钮：

```text
u16 frame_length = 24
u16 opcode       = 0x002E
u32 action_id    = 0x000003B9
u32 action_value = 1
u32 arg1         = 0
u32 arg2         = 0
u32 sequence     = 当前请求序号
```

录制中的成功样例：

```text
00 18 00 2E 00 00 03 B9 00 00 00 01 00 00 00 00 00 00 00 00 00 00 00 18
```

服务端处理成功后，原 Flash 客户端还会自行发送同 opcode、`action_id=0x03BA` 的界面/背包刷新确认。该包由 Flash 收到物品回包后自然生成，自动化不重复注入。

## 成功和停止条件

单次捐献必须同时满足：

- 临时捐献栏回包已确认，且已经发送 `action_id=0x03B9` 的按钮请求；
- `SC_SYSTEM_MESSAGE (0x0029)` 包含 `感谢你为帮派作出的贡献` 或 `帮派贡献增加`；
- 同一源背包格收到数量减少的 `SC_ITEM_UPDATE`，或收到 `SC_ITEM_REMOVE`。

两项都确认后才会再次访问 NPC。这样即使包到达顺序改变，也不会因只看到一条提示而重复提交。

以下情况自动结束或失败停发：

- 服务端捐献提示包含次数、上限、用尽或不可继续等语义；
- NPC 功能列表不再提供 `帮派捐献`；
- 背包中已无目标道具；
- 达到界面配置的安全上限；
- 成功提示后 4 秒仍没有背包扣减，或其他阶段超时；
- 服务端提示 `你还没有放入物品呢`（说明临时栏确认与按钮请求没有契合）；
- ACTIVE 发包模式被关闭、连接关闭或发送失败。

“自动捐献”和“自动除暴”使用同一个独占自动化锁，避免两套状态机同时竞争全局请求序号。

## 使用方式

角色登录后站到帮会捐献官附近，打开工作台的 `自动捐献` 页，直接点击 `开始自动捐献`。程序会自动完成“放入碎片”和“点击捐献”两步。NPC ID 默认已填入 `93631`；背包格、数量、功能 ID 和请求序号均不需要用户填写。
