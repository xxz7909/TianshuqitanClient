# v5 除暴安良协议与自动化状态机

## 分析样本

- `session-20260831-112228-317-除暴按量环节示例.sqlite`：确认接任务、任务 HTML、传送、目标 NPC、战斗及返回舞修罗的单环链路。
- `session-20260831-182234-951-一次完整的除暴安良.sqlite`：原子操作边界 `745..1703`，确认第 2 至第 10 环的动态目标，以及第 10 环后再次访问舞修罗领取轮次奖励的分支。

数据库中的文本表明玩法名称是“除暴安良”。每轮 10 环，每日可进行 2 轮；玩家拥有通缉令时可额外增加 1 轮。通缉令消耗对话尚无独立录制样本，因此程序只有在用户勾选“有通缉令时追加第3轮”时才允许确认包含“通缉令”的服务端对话，绝不默认消耗道具。

## 通用编码

所有已确认游戏帧均为大端序：

```text
u16 frame_length       // 包含四字节帧头
u16 opcode
byte body[]
```

字符串使用 `u16 UTF-8字节数 + UTF-8字节`。进入游戏后的客户端业务请求通常以大端 `u32 request_sequence` 结尾；该值在同一游戏连接上持续递增，不能复制录制值。

## 已确认报文

| 方向 | Opcode | 含义 | 已确认正文 |
| --- | ---: | --- | --- |
| C→S | `0x00B5` | 点击任务/传送链接 | `u32 0xFE + string npcId + string mapId + string "x=y" + u32 seq` |
| C→S | `0x0016` | 访问 NPC/任务目标 | `u32 npcId + u32 seq` |
| S→C | `0x001D` | NPC 功能列表 | 开头为 `u32 npcId`；“除暴安良”后紧跟功能字符串 `"374"` |
| C→S | `0x0017` | 选择 NPC 功能 | `u32 npcId + string functionId + u32 seq` |
| S→C | `0x005C` | 模态确认框 | `u32 contextId + string title + string content + string randomToken + ...` |
| C→S | `0x004C` | 确认模态框 | `u32 contextId + string randomToken + string "ok" + u16 0 + u32 seq` |
| S→C | `0x003E` | 任务更新 | 包含任务名、任务描述 HTML、返回 NPC HTML 等字段 |
| S→C | `0x002C` | 战斗行动提示 | 每次提示只发送一次推进请求 |
| C→S | `0x001F` | 推进战斗回合 | `u32 seq` |
| S→C | `0x0019` | NPC 从地图移除 | `u32 npcId`；与当前除暴目标相同即可确认战斗结束 |
| S→C | `0x0029` | 系统消息 | 包含单环经验、轮次奖励、活跃度和限制提示 |

### 传送链接

录制中的三个代表性请求：

```text
皇城皇宫：npc=14,    map=12, x=24, y=28
舞修罗：  npc=8011,  map=13, x=30, y=100
任务目标：npc=900xx, map/坐标来自实时任务 HTML
```

完整录制确认从古道、黄金港口等多个任务地图都可直接用 `8011/13/30=100` 返回舞修罗，所以自动化默认直接前往舞修罗。凌昌城到舞修罗的直接路径是基于同一服务端事件协议作出的推断；界面仍保留“先经皇城皇宫”的兼容开关，便于服务器若实施来源校验时回退。

所有 `0x00B5` 之后的“是否传送”框都会下发新的随机 token。自动化从实时 `0x005C` 取出 `contextId/token` 后再构造 `0x004C`，不会重放样本中的 token。

### 彩色任务 HTML 与 Base64

完整录制中的 `0x003E` 任务描述是原始 UTF-8 HTML，例如：

```html
第10次，一群暴徒出现在
<a href='event:x:11,y:64,m:10,n:90002'>
  <u><font color='#126D00'>(古道(11,64)</font></u>
</a>
附近烧杀掠抢，速去消灭他们
```

返回链接同样位于该包中：

```html
<a href='event:x:30,y:100,m:13,n:8011'><u>舞修罗(30,100)</u></a>
```

解析器提取 `event:x:X,y:Y,m:MAP,n:NPC`，把 `n=8011` 识别为返回链接，其余链接作为当前战斗目标。为了兼容其他服务端路径，解析器也会检测 UTF-8 字符串中的 Base64 文本，解码后再执行同一链接解析；不会假设目标 NPC、地图或坐标固定。

## 一环状态序列

```text
前往舞修罗 0x00B5
  -> 实时确认传送 0x005C/0x004C
  -> 地图起点 0x0016(S→C)
  -> 访问舞修罗 0x0016(C→S, npc=8011)
  -> 功能列表 0x001D
  -> 选择除暴安良 0x0017(function="374")
  -> 首环可能出现接任务确认 0x005C/0x004C
  -> 任务更新 0x003E
  -> 解析并前往动态目标 0x00B5
  -> 实时确认传送 0x005C/0x004C
  -> 访问动态 NPC 0x0016(C→S)
  -> 战斗提示 0x002C -> 推进 0x001F
  -> 目标移除 0x0019
  -> 返回舞修罗
```

战斗推进不是固定定时连发。程序只在处于当前目标的战斗状态并收到一个新的 `0x002C` 后发送一个 `0x001F`，避免重复推进或在非战斗状态误发。

## 十环轮次奖励

任务 HTML 中的“第 N 次”是本轮环数的权威来源。第 10 环目标移除后仍须：

1. 用任务内的舞修罗链接返回；
2. `0x0016(npc=8011)` 再次打开舞修罗；
3. 从实时功能列表取出“除暴安良/374”，发送 `0x0017`；
4. 等待 `0x0029` 中的“任务奖励：技能经验...”以及随后活跃度/背包更新；
5. 只有收到轮次奖励后才把这一轮标记完成。

完整样本第 10 环的尾部为：

```text
CS 0x0016 npc=8011
SC 0x001D 舞修罗功能列表
CS 0x0017 function="374"
SC 0x0029 任务奖励：技能经验1236
SC 0x0029 你获得了2点活跃度
```

若计划继续下一轮，领奖完成后再次访问舞修罗并选择除暴安良。前两轮由服务端每日次数控制；勾选通缉令选项时才允许第三轮的道具确认。

## 安全与失败策略

- 自动化开始时临时开启 EasyHook ACTIVE 发包模式；若原先未开启，停止、失败或完成后恢复为关闭。
- `Ctrl+Shift+F12` 紧急旁路会立即停止状态机和后续定时发包。
- 连接 ID、请求序号、确认 token、目标 NPC、地图和坐标都来自实时连接/报文。
- 任何功能项缺失、连接关闭或阶段超时都会停止，不发送猜测报文；错误会写入审计日志和当前会话库。
- 当前实现不修改服务端下发的任务、奖励或背包数据，只监听状态并发送原客户端已确认格式的请求。
