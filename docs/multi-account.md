# 多开与多账户运行模型

## 使用方式

1. 打开工作台的“多开管理”页。
2. 新建账户，填写显示名称、游戏账号、密码、线路、角色和自动登录开关，然后点击“保存账户”。
3. 点击“启动选中账户”可重复启动同一账户；点击“启动全部未运行”会为所有当前没有实例的账户各启动一个客户端。
4. 窗口标题包含账户名称、PID 和实例短 ID，便于区分各窗口。

密码不会进入进程命令行或账户目录的明文清单。每个账户的密码保存在 `data/accounts/<account-id>/login.json`，并使用当前 Windows 用户的 DPAPI 加密。旧版 `data/secrets/auto-login.json` 会在首次启动时复制到默认账户。

## 隔离边界

每次启动都会生成新的 `data/instances/<instance-id>` 目录，包括直接双击启动。实例拥有独立的：

- `sessions/`：抓包 SQLite 和语义文件名；
- `logs/`：启动器及鼠标诊断日志；
- `configuration/`：协议、规则、Lua 和运行时 profile 副本；
- `audio-cache/`：BGM 原始音频及过滤缓存；
- `instance.json`：PID、账户、启动/结束时间和可执行文件信息。

原子操作模板保存在 `data/accounts/<account-id>/operation-templates.json`，因此同一账户重启后仍会保留、不同账户之间不会串模板。同一账户同时多开时，模板通过跨进程互斥锁和原子替换安全共享。

EasyHook、抓包状态机、自动登录、自动除暴和 BGM 代理都在各自进程内运行。BGM 代理强制使用系统分配的动态端口，因此多个实例不会争用 `audioFilterProxyPort`。账户清单、加密凭据和该账户的模板是需要跨实例共享的启动器状态，写入时使用跨进程互斥锁及原子替换。

全局快捷键只由当前激活窗口注册；窗口失去焦点后立即释放。后台实例也不会执行鼠标跳转防护或释放鼠标裁剪，避免一个客户端操作另一个客户端的输入状态。

## 启动参数

多开管理器内部使用以下参数，正常使用界面时不需要手工填写：

```text
--account <default 或 32 位 GUID>
--instance <32 位 GUID>
--window-slot <0..31>
--profile <源 profile 路径>
```

密码不通过参数传递。实例参数会严格验证，不能通过账户 ID 或实例 ID 跳出数据目录。

## 生命周期

`instance.json` 在进程启动时登记，在正常关闭时写入 `EndedUtc`。多开管理页同时校验 PID、进程启动时间和结束标记，因此崩溃遗留的记录不会被误认为正在运行。删除账户前会检查该账户是否仍有活动实例，当前账户和默认账户不能删除。
